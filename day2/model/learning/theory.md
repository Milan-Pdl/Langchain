# Day 2: Models in LangChain

## 1. What are Models?

Models are the core components through which a LangChain application communicates with artificial intelligence models.

An AI provider may provide services such as:

- generating text
- answering questions
- converting text into numbers (vectors)
- supporting chat conversations

LangChain provides a standardized interface for these services. This means that application code can be written in a similar way even when the underlying provider or model changes.

For example, instead of learning a completely different API for OpenAI, Anthropic, and Google, we can use LangChain model abstractions and change the model configuration while keeping the rest of the application structure consistent.

```text
User input
   |
   v
LangChain model interface
   |
   v
Model provider API
   |
   v
Generated response or embedding
```

## 2. Model Categories

The diagram shows this hierarchy:

```text
Models
├── Language Models
│   ├── LLMs
│   └── Chat Models
└── Embedding Models
```

### 2.1 Language Models

Language models receive natural-language text and generate natural-language text.

They are divided into two categories:

1. LLMs
2. Chat Models

### 2.2 LLMs

LLMs, or Large Language Models, are mainly used for direct text completion.

The model receives a prompt and predicts a useful continuation.

```text
Input text:
"The capital of India is"

Generated text:
"New Delhi."
```

A typical use case is summarization:

```text
Input:
"Summarize: LangChain helps developers build applications with language models."

Output:
"LangChain simplifies the creation of applications using language models."
```

LLMs generally use a text-in/text-out interface.

### 2.3 Chat Models

Chat models are designed for conversational interactions. They understand messages associated with roles such as:

- `system`: Defines instructions or the behavior of the assistant
- `user`: Represents the user's message
- `assistant`: Represents a response generated by the model

Example:

```text
System: You are a helpful Python tutor.
User:   What is a list?
Assistant: A list is an ordered, changeable collection of items.
User:   Give me an example.
Assistant: numbers = [10, 20, 30]
```

Chat models are usually more suitable for chatbots, assistants, and multi-turn conversations because they preserve the roles of conversation messages.

Modern chat models often support system instructions, conversation history, JSON output, tool calls, and multimodal input.

## 3. Embedding Models

Embedding models convert text into a numerical vector.

```text
"A golden retriever is playing" -> [0.18, -0.42, 0.71, ...]
"A dog is playing"             -> [0.21, -39.0, 0.67, ...]
"Python is a programming language" -> [-0.88, 0.12, 0.45, ...]
```

An embedding is a point in a high-dimensional space. Text with similar meanings normally produces vectors that are close to each other.

Embedding models do **not** generate a human-readable answer. Their main purpose is comparison and retrieval.

```text
Text 1: "How do I reset my password?"
Text 2: "Password recovery procedure"

Similarity: High

Text 1: "How do I reset my password?"
Text 2: "What is the price of a laptop?"

Similarity: Low
```

Common embedding use cases include:

- semantic search
- document similarity
- recommendation systems
- duplicate detection
- retrieval-augmented generation (RAG)

## 4. Input and Output by Model Type

| Model type | Input | Output | Example |
|---|---|---|---|
| LLM | Text prompt | Generated text | "Summarize this article" |
| Chat model | Chat messages with roles | Assistant message | "Explain Python variables" |
| Embedding model | Text | Numerical vector | `[0.12, -0.45, 0.88, ...]` |

## 5. General Conceptual Example

Suppose we want to build a travel assistant:

```text
User: "Which places should I visit in Nepal?"

1. Send the user question to a Chat Model.
2. The Chat Model generates a destination suggestion.
3. Convert relevant travel documents into Embeddings.
4. Retrieve documents similar to the user's question.
5. Add the retrieved documents to the prompt.
6. Ask the Chat Model to provide an answer using those documents.
```

In this example:

- **Chat Model** creates the conversational response.
- **Embedding Model** converts text into vectors for semantic matching.
- **Retriever** finds relevant documents using those vectors.

## 6. Key Differences

### LLM vs. Chat Model

| LLM | Chat Model |
|---|---|
| Text completion-oriented | Conversation-oriented |
| Uses a string prompt | Uses role-based messages |
| Suitable for simple generation tasks | Suitable for assistants and multi-turn chat |
| No explicit user/assistant structure | Supports system, user, and assistant roles |

### Language Model vs. Embedding Model

| Language Model | Embedding Model |
|---|---|
| Produces text | Produces vectors |
| Used to answer or generate | Used to compare or retrieve |
| Text-in/text-out | Text-in/vector-out |

## 7. Important Points

- A model is a provider-specific AI system.
- LangChain provides a common interface for working with models.
- Language models generate human-readable text.
- LLMs and chat models are both language models.
- LLMs are completion-oriented, while chat models are conversation-oriented.
- Embedding models convert text into vectors.
- Embeddings are used for similarity search and information retrieval.
- Models alone are stateless; LangChain memory is needed to manage conversation history.
